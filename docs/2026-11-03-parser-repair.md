# 用量解析修复记录

## 范围与原因

旧插件报告把工具细分、时间、会话、回合排行写成固定的“不可得”，没有使用本地已经存在的事件时间、调用标识和工具返回记录。按文件创建时间筛选还会遗漏跨日续聊，并把范围外的调用计入今天。

## 本次实现

- 用量按事件时间选择，按会话和响应标识去重；不累计线程级累计字段。
- 分别生成小时、会话、用户回合的输入与输出排行。
- 使用调用标识关联工具名和返回；展示返回次数、字符量、占工具返回字符比例和最大单次大小。
- 单列 `exec` 组合工具；不猜测其多个内层调用分别贡献多少输出。
- 完整请求样本也按事件时间筛选；时间缺失的样本不混入时间范围统计。
- 保持 MCP 返回聊天正文，不生成持久化分析报告。

## 验证跟踪

- 已验证：跨日续聊、同响应去重、跨日工具关联、请求样本边界、组合工具分类。
- 已本地验证：132 项全量测试通过；`0.1.22` 安装缓存的三份分析脚本与源码逐字节一致。
- 已验证安装缓存的 MCP 协议调用：本机“今天”返回 31 份含用量记录的文件、205 次组合工具返回、603,555 个返回字符，且三个排行均存在。数据为验证时快照，后续调用会变化。
- 桌面斜杠命令完整交互尚未验收，不以脚本或协议测试替代。

## 限制

本地工具正文字符量不是模型请求的精确 Token 占比。缺少完整请求时，系统提示、Skill 等类别的精确用量仍不可得。组合工具的内部输出没有逐项边界时不能可靠进一步拆分。时间范围分析需要检查历史文件中的事件，才能纳入早先创建、今天仍在继续的会话；默认当前会话仍先限定对应文件。
