# 输入工具定义补估

## 范围

报告聚焦可优化的输入，输出只保留总计。助手历史仍属于后续输入内容，不按思考正文等输出类型另行展开。基础指令仅提示“可能与实际发送版本存在一定误差”。

## 工具定义来源

1. 解析日志 `response_item.additional_tools`，将工具名称、用途、参数结构归入工具定义。
2. 已保存的请求样本继续统计顶层 `tools` 与历史内声明。
3. 对有实际调用用量、可识别模型、没有保存工具声明的会话，调用当前原生 Codex 构造默认工具定义，作为独立的“工具定义（原生补估）”计入正文估算合计。

补估每会话计一次，不将其乘以调用数冒充实际累计输入。同一会话的多个文件不重复补估，同模型在单次报告中仅查询一次。历史版本、默认配置与原会话可能不同，报告使用简短说明区分历史声明与当前基线。它不重建历史插件及 MCP 工具目录。

## 原生调用方式

`debug prompt-input` 只输出输入项，不能直接取到标准 Responses 协议的顶层工具定义。改用原生 `codex exec --ephemeral`，在独立 CODEX_HOME 和空目录中连接本地模拟接口，读取它组装的首轮工具声明。模拟接口立即返回结束消息，不发出工具调用，不连接真实模型，也不使用模拟接口的用量记录统计实际消耗。

临时运行目录默认在 `D:/ai_soft/tokenUsage/native-tools`，退出后清理。子进程 15 秒超时，超时由 subprocess 终止；服务线程随后关闭。单次补估失败不影响已有用量报告。成功结果仅在 MCP 进程内缓存，缓存键含原生程序路径、修改时间和模型。

## 验证

原生桌面附带 `0.166.0-alpha.6`，以 `gpt-5.1-codex` 实测取得 9 项顶层声明，本地分词估算 4,224 Token；这是此模型及默认配置的样例，不是所有会话的固定值。

回归验证包括保存声明优先、会话去重、相同模型仅查询一次、时间范围排除、失败隔离、基础指令提示，以及现有报告与请求解析测试。聊天窗最终呈现仍与本地逻辑验证区分。
