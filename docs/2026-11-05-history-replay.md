# 历史重复携带量还原任务跟踪

## 已确认方案

按会话事件顺序重放输入历史，在本次模型首个输出项前冻结输入，收到对应用量记录后累计；禁止把本次输出计入本次输入。分析时间范围只筛选调用，不截断此前的历史。使用本地分词器估算可见正文，和同批调用的实际输入比较。

压缩记录提供 replacement_history 时替换历史；缺失替换历史时暂停该段归因，直到出现有效检查点。工具结果按保存的截断元数据重放原生 UTF-8 首尾裁剪规则。区分会话和调用标识，避免同一工具标识在不同会话串账。

实际请求样本仍单独展示；历史重放不与请求样本叠加，避免重复计算。无日志证据的媒体、加密思考和协议开销不伪造为正文 Token。

## 状态

- 已核查：原生代码提交 4f093f2748667f3b0e6a07e3d4055121cbd3ce64、当前真实日志顺序、25 个历史压缩检查点。
- 已编码：重放状态机、截断处理、累计分类与工具重复表、报告接入；优化建议优先使用累计输入估算。
- 已本地验证：183 项测试通过，覆盖跨天、输出归属、重复文件、分片继承、压缩/回滚、截断、多会话、并行返回、缺失边界及工具定义查询失败缓存。
- 已交叉验证：原生 Codex 模拟接口保存的两次实际请求，其工具结果正文累计为 1,642 Token，历史重放为 1,642 Token。
- 已全历史验证：66 个会话、3,025 次调用完成重放，分类合计及工具逐条累加一致；关闭额外原生工具探测的重放耗时 15.76 秒。
- 已安装并验证：0.1.41 安装版 MCP，“分析今天会话”耗时 10.58 秒；重建 145 次调用，正文累计估算 14,741,981 Token，同批实际输入 16,043,347 Token。数字随会话新增调用变化。
- 未实机验收：聊天端最终展示，以及既有 MCP 连接自动切换版本。

## 实现依据

核对原生 `core/src/context_manager/history.rs` 的历史记录/截断与输入过滤；`utils/output-truncation/src/lib.rs` 的序列化预算余量；`utils/string/src/truncate.rs` 的 UTF-8 首尾裁剪；历史检查点的 replacement_history 和 replacement_history_metadata；回滚事件的 num_turns。

用量记录在当前模型响应项之后出现，所以在第一个模型输出项前冻结快照，收到用量后再累计。接收到新用户输入、工具结果或回合结束时，清除未匹配用量的旧边界。压缩模型调用通过 compaction_response_id 排除，不将其当作普通会话输入。

## 验证中发现并修正的问题

- 首轮重放约 39 秒：为无关历史重复分词。改为跳过无关独立会话，从范围前最近的压缩检查点恢复；同会话多文件保留前序历史，避免丢失跨天输入。
- 多模态返回不能把图片/音频编码当文本分词。正文分类、工具细分及重放均只统计可见文本，三条路径一并修复。
- 压缩后记录项编号可能改变，但同一工具调用及正文应继续关联；使用会话、调用标识、正文摘要关联，而非记录项编号。

## 已知边界

这是可见输入正文的重放估算，不是完整请求副本。按已记录的压缩和文本截断处理；未保存的请求调整、图片/音频输入、加密思考及协议开销不能从正文推算。基础指令与实际发送版本可能有误差；缺少工具定义时仍使用当前原生基线补估。

缺失调用边界、不可读记录、没有替换历史的压缩以及无法回滚的检查点，均跳过受影响调用，不用整段旧历史强行补齐。有有效检查点后可以恢复。多模态列表的文字拼接与裁剪是近似，不声称完全复刻媒体预算处理。

报告对照只使用已重建的同批调用；历史重放和实际请求样本分别展示，不把两者相加。重复次数只统计用户选择范围内的调用，不等于这条内容终身被使用的次数。
