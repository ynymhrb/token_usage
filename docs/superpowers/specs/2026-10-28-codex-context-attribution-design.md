# Codex 上下文构成归因设计

## 目标

为保存了 `*.llm_calls.jsonl` 请求结构的 Codex 会话生成上下文构成报告，找出静态指令、工具定义、用户消息、历史消息、工具参数和工具结果中最值得压缩的部分。

## 证据口径

- 能与请求结构关联的 `token_usage_record` 输入 Token 总量标记为精确值；当前找不到关联记录时，明确报告为缺失，不以别的调用代替。
- 分类占比来自保存的请求 JSON 的字符量；只有拿到同一次调用的精确输入 Token 时才校准为估算 Token，否则只输出字符量和相对占比。
- `instructions` 已合并系统提示、项目规则和 Skill，因此只报告为“静态指令”，不得伪造三者的独立精确值。
- 没有 `*.llm_calls.jsonl` 的会话必须报告覆盖缺口，不得从原始 rollout 猜测构成。

## 分类

- 静态指令：`request.instructions`。
- 工具定义：`persisted_dynamic_tools`。
- 用户消息、开发者消息、助手历史：`input` 内 `message` 按 `role` 分组。
- 工具参数：`function_call`、搜索调用。
- 工具结果：`function_call_output`、搜索结果、工具搜索结果。
- 不可归因：推理密文、压缩点及未知输入项。

## 输出与建议

报告输出每个类别的字符量、校准后的估算 Token、占比、覆盖调用数及证据等级。建议仅在类别占比高且覆盖足够时产生，并明确建议针对的是静态指令、工具定义或历史工具结果。
