# 分析请求等待 300 秒的故障修复

## 证据与原因

故障会话 `01a1a7cd-4c0e-7561-84ab-5d739b200247` 的本地日志记录了调用参数 `scope: "分析今天会话"`。旧范围解析只接受“今天”，因此立即抛出范围错误。服务错误响应统一使用空请求编号，客户端无法关联待处理请求，最终等待 300 秒超时。

真实数据分阶段测量耗时约 4—5 秒，并未复现计算卡住。当前聊天已有 MCP 连接返回了旧版报告，说明安装新版本不能证明所有既有连接已更新。

## 修复与验证状态

- 已编码：支持“分析今天会话”“今天的会话”“统计昨天的会话用量”等明确日期表达；不将“今天或昨天”等歧义范围扩大为历史扫描。
- 已编码：参数错误和内部异常保留原请求编号；通知不产生响应、不执行分析；格式错误使用独立 JSON 解析错误。
- 已编码：同插件受控工具服务的错误编号丢失问题一起修复。
- 已本地验证：159 项测试通过，包含字符串编号、零编号、通知、内部异常及失败后的下一次请求。
- 已安装：0.1.39；安装缓存中的真实 MCP 服务对“分析今天会话”返回完整报告，连同后续非法范围请求共耗时 4.95 秒。错误响应携带对应编号。
- 未实机验收：原聊天连接是否切换到新服务。不能把安装目录协议验证说成聊天窗已恢复。

没有延长客户端超时时间，没有使用脚本替代用户的 MCP 分析入口。诊断脚本仅用于定位及验证服务实现。
